# Agent guide

Instructions for AI coding agents working in this repository. Humans: see [CONTRIBUTING.md](CONTRIBUTING.md).

## Repository map

- `data/entries/<section>.yml`: the list content. One file per top-level section in `data/taxonomy.yml`.
- `data/taxonomy.yml`, `data/tags.yml`, `data/sources.yml`, `data/glossary.yml`: section tree, tag vocabulary, upstream sources, glossary.
- `data/generated/metadata.json`: written by `pnpm enrich` and a weekly bot. Do not edit by hand.
- `schema/`: JSON Schemas for every data file.
- `scripts/`: TypeScript run directly by Node 24+ (native type stripping, `.ts` import extensions, erasable syntax only).
- `README.md`: generated by `pnpm build:readme`. Never edit it directly.

## Adding or changing entries

1. `pnpm add-entry <url> --section <section/subsection> [--type tool] [--via source-id]`
2. Replace the `TODO` description with one neutral sentence in your own words (20–160 chars, ends with a period, does not start with the name, no superlatives, no unverified numbers).
3. Add `tags` from `data/tags.yml`, and `paper: {venue, year, code}` for papers.
4. Verify the URL loads and the facts in the description are true **as of today**. Projects get renamed, archived, and acquired often; check the repository page, not your training data.
5. `pnpm build && pnpm check`

## Rules

- Never copy descriptions or text from other lists or from a project's own marketing copy. Credit discovery sources with `via`.
- One entry, one subsection. Do not add the same URL twice.
- Keep `featured: true` to at most three entries per subsection, and only when a human asked for it.
- Disclose AI assistance in the PR description, and say what you verified by hand.
